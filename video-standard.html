# 视频处理标准（李书远数据库）

状态：生效（2026-08-17 魅惑立）\ 适用范围：李书远数据库（资料库空间）的所有文件上传\ 遵守对象：所有向本数据库上传文件的 Agent / 用户

## 核心规则（一句话）

凡是超过 100MB 的任何文件，都必须分割到 100MB 以内（建议 ≤90MB 留余量），才能上传到本数据库。

## 为什么

资料库网盘（drive）通道单文件上限 100 MiB，超出直接失败，不分片重试。

视频/大型文件若不做处理，会直接上传失败或被拒。

## 适用范围

视频（mp4 / mov / mkv 等）——最常见

音频（mp3 / wav 等大文件）

压缩包 / 大型文档 / 其他任何 >100MB 的文件

图片走图片通道（上限 10 MiB），不在本规则范围

## 分割方法（视频，无损按时长法）

⚠️ FFmpeg 的 -segment_size（按字节分割）在 gyan.dev Windows 版不可用（实测 8.1/9.0.1 均报 Unrecognized option）。必须用按时长法：

探测：ffprobe -v error -show_entries format=duration,size -of json input.mp4

算码率：平均码率 ≈ 文件总大小 ÷ 总时长

算每段时长：每段时长（秒）= 90MB ÷ 平均码率（留 10% 余量保险）

分割：ffmpeg -i input.mp4 -c copy -f segment -segment_time -reset_timestamps 1 输出_%03d.mp4

-c copy：不重新编码，画质无损、速度快

校验：确认每段文件大小 ≤100MB（建议 ≤90MB）

## 上传流程

检查文件大小（ls -la / 文件属性）

≤100MB → 直接上传

100MB → 按上方方法分割 → 逐段上传

每段命名保持序列（如 案例视频_001.mp4、案例视频_002.mp4），备注里注明"分片 N/M"

## 备注规范

分割上传的文件，每条记录/每段文件的备注必须写明：原文件名、总大小、分片数、本片序号、分割时间、分割工具与版本（如 FFmpeg 9.0.1）

示例备注：源文件 案例视频.mp4 256MB，分 3 片，本片 1/3，90MB，FFmpeg 9.0.1 按时长法分割 2026-08-17

## 禁止事项

禁止把 >100MB 文件原样上传（会失败）

禁止用 -segment_size（此选项在本机 FFmpeg 不可用）

禁止重新编码降质（除非用户明确要求压缩）

本标准随数据库使用手册同步维护。
